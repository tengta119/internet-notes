这个 Skill 本身不是一个独立运行的软件。它相当于给 **Pi / Claude Code / Codex 等 Agent 加一套“整理 Edge 收藏夹的工作规范”**。真正负责操作 Edge 的，是 `chromium-bookmarks-mcp`。

你需要把两者接起来：

```
Pi / Claude Code / Codex
        │
        ├── bookmark-organizer Skill
        │       └── 决定“应该怎么整理”
        │
        └── chromium-bookmarks-mcp
                └── 真正读取/修改 Edge 收藏夹
```

## 1. 先安装 `chromium-bookmarks-mcp`

你之前的环境里已经在使用 **Pi**，所以我建议直接按 Pi 的方式部署。

先把 `chromium-bookmarks-mcp` 按它项目 README 的要求安装并连接到 Edge。安装完成后，最重要的是确认 Agent 能看到类似这些 MCP 能力：

```
ping
bookmark_get_tree
bookmark_search
bookmark_get
bookmark_count

bookmark_create
bookmark_update
bookmark_move
bookmark_delete

bookmark_batch_move
bookmark_merge_folders
bookmark_deduplicate
bookmark_batch_delete

bookmark_export_html
bookmark_import_html

bookmark_find_duplicates
bookmark_check_dead_links
```

你的 Skill 已经针对这一套工具设计好了。

------

# 2. 安装 `bookmark-organizer`

你下载的压缩包：

bookmark-organizer-skill.zip

解压后就是：

```
bookmark-organizer/
├── SKILL.md
├── README.md
└── references/
    ├── decision-rubric.md
    └── output-template.md
```

关键文件是：

```
bookmark-organizer/SKILL.md
```

把整个 `bookmark-organizer` 目录放进你的 Agent 的 **skills 目录**，不要只复制 `SKILL.md`。

------

# 3. 如果你用的是 Pi

你之前用的是 Pi，所以这里重点说 Pi。

首先查看 Pi 当前加载的 Skill：

```
pi
```

进入后可以查看启动信息，确认 Skill 是否被加载。

如果你的 Pi Skill 目录是：

```
~/.pi/agent/skills/
```

那么最终应该类似：

```
~/.pi/agent/skills/
└── bookmark-organizer/
    ├── SKILL.md
    ├── README.md
    └── references/
        ├── decision-rubric.md
        └── output-template.md
```

如果你不确定当前 Pi 的 Skill 路径，可以在 Pi 中让它自己检查：

```
Where do you load skills from?
```

或者查看 Pi 的启动帮助。

------

# 4. 启动 Pi

确保：

```
Edge
  ↓
chromium-bookmarks-mcp
  ↓
Pi
```

都已经运行。

然后进入 Pi。

第一次不要让它直接修改。

直接输入：

```
使用 bookmark-organizer Skill，分析我的 Edge 收藏夹。
先执行只读分析，不要修改任何收藏夹内容。
```

Skill 会要求 Agent 执行类似：

```
ping
↓
bookmark_get_tree
↓
bookmark_count
↓
bookmark_find_duplicates
↓
bookmark_check_dead_links
↓
分析分类
↓
生成整理方案
```

最终你应该得到类似：

```

疑似失效：38
需要重新分类：512

Bookmarks

│   ├── Agent

│
├── Development

│   ├── Spring

├── Research
```

**到这里它不应该修改任何东西。**

------

# 5. 然后让 Agent 给你“整理计划”

例如你可以继续输入：

```
基于刚才的分析，生成完整的 Bookmark Migration Plan。

要求：
1. 展示新的目录结构
2. 统计每个目录将移动多少收藏
3. 列出高风险分类
4. 单独列出重复收藏
5. 单独列出疑似失效收藏
6. 单独列出建议重命名的收藏
7. 不执行任何修改
```

这一步非常重要。

你可以先检查 AI 是否理解你的收藏习惯。

------

# 6. 确认后才执行

当你满意后，再输入：

```
批准这个整理方案。

按照刚才的 Migration Plan 执行：
1. 先备份
2. 先 dry-run
3. 检查 dry-run 结果
4. 再执行实际修改
5. 最后重新读取 Edge 收藏夹进行验证

禁止扩大修改范围。
```

Skill 里已经规定了这个顺序：

```
Backup
   ↓
Dry Run
   ↓
Apply
   ↓
Verify
```

所以正常情况下 Agent 不应该直接：

```
bookmark_delete
bookmark_batch_delete
```

而是先完成备份和预执行。

------

# 7. 推荐你实际采用“两轮整理”

不要一次让 AI 把 2000 个收藏全部重构。

比较稳妥的是：

### 第一轮：只整理结构

```
建立目录
↓
移动收藏
↓
保留所有收藏
```

不要删除。

例如：

```
1500 个收藏
      ↓
重新分类
      ↓
1500 个收藏
```

这样风险很低。

### 第二轮：清理

等结构稳定后，再：

```
重复 URL
↓
死链
↓
过时内容
↓
无意义收藏
```

再单独处理删除。

这样比“分类 + 去重 + 死链 + 删除”一次完成安全很多。

# 8. 你还可以直接给它一些额外规则

例如你作为一个后端开发方向的人，可以告诉 Agent：

```
我的主要使用领域包括：

Java
Spring
MySQL
Redis
RocketMQ
分布式系统
AI
LLM
Agent
MCP
科研
算法
面试
开发工具

这些领域应该尽量保持稳定的一级/二级分类。

不要因为一个项目同时属于多个领域而复制收藏。
优先根据“我以后为什么会再次打开这个页面”决定分类。
```

这样 AI 的分类结果通常会比完全自由发挥稳定。

------

# 9. 最推荐的实际使用命令

以后你甚至可以把它当成几个“工作模式”。

### 分析

```
使用 bookmark-organizer：
分析我的 Edge 收藏夹，只读，不修改。
```

### 查重

```
使用 bookmark-organizer：
检查我的 Edge 收藏夹中的重复收藏。
只报告，不删除。
```

### 查死链

```
使用 bookmark-organizer：
检查 Edge 收藏夹中的失效链接。
把 404、403、登录限制、超时分别统计。
不要删除。
```

### 设计分类

```
使用 bookmark-organizer：
重新分析我的整个收藏夹，并提出一套长期可维护的信息架构。
不要修改。
```

### 执行

```
使用 bookmark-organizer：
执行刚才已经批准的整理方案。
先备份，再 dry-run，再 apply，最后 verify。
```

------

# 10. 一个非常重要的点

**不要把 Skill 当成 MCP。**

两者职责完全不同：

```
chromium-bookmarks-mcp
=
“手”

bookmark-organizer
=
“操作规程 + 大脑约束”

Agent
=
“负责判断”
```

例如 MCP 只知道：

```
bookmark_move(
    bookmark_id,
    folder_id
)
```

但它不知道：

> “这个 Java 教程到底应该放 Java 下面还是 Interview 下面？”

这个判断就是 `bookmark-organizer` Skill 的作用。

## 你的最终目录建议

在你的 Pi 环境里，我建议最终形成：

```
~/.pi/agent/
│
├── skills/
│   └── bookmark-organizer/
│       ├── SKILL.md
│       ├── README.md
│       └── references/
│
└── ...
```

然后：

```
Microsoft Edge
      │
      ▼
chromium-bookmarks-mcp
      │
      ▼
      Pi
      │
      ▼
bookmark-organizer
      │
      ├── Analyze
      ├── Propose
      ├── Backup
      ├── Dry-run
      ├── Apply
      └── Verify
```

**最先做的一步不是整理收藏夹，而是先验证 Pi 是否已经成功加载 `chromium-bookmarks-mcp`。**

你可以在 Pi 里直接输入：

```
测试 chromium-bookmarks-mcp。
先调用 ping，然后读取我的 Edge 收藏夹树。
只读，不要做任何修改。
```

如果这一步成功，后面的 `bookmark-organizer` 基本就可以直接工作。
